- **Saving off** (Settings): nothing is written to `localStorage`, and the saved store is removed.
- **Not encrypted.** Anyone with access to the unlocked phone and browser, or its backups, can read `localStorage`. (Already an open item in HANDOFF.md.) **One exception (6.21):** the optional diary lock encrypts diary entries on the phone; everything else is not encrypted.
- **Diary lock (6.21, off by default):** done entirely on the phone with the browser's Web Crypto API. A key is derived from the passcode with PBKDF2 (SHA-256, 310,000 iterations, random 16-byte salt); entries are encrypted with AES-GCM 256 with a fresh random 12-byte IV on every save; a known value is encrypted the same way to check the passcode. Stored: salt, encrypted check value, IV, ciphertext. **Never stored: the passcode or the derived key** (the key lives in memory only while the diary is open, and is dropped when the person leaves the diary, when the page is hidden, or after 5 minutes). A forgotten passcode can't be recovered: the only option is deleting the diary.
- **Free text is never stored** (except song lines, Find something photo notes and "Remembering" notes, and only when the person taps Keep). The grief path's name field (6.20, "Tell one person") is checked, used for the prepared texts in memory, and never saved. The three-things fields, Thought Parking, the spiral "own step" and "Thank you for ___" are checked and then discarded. Verified after a RED entry: not in `localStorage`, not in `session`/`ui`, not in the page.

## 2. Network: what leaves the phone

**The app makes no network requests of its own.** No `fetch`, `XMLHttpRequest`, `sendBeacon`, WebSocket or EventSource; no analytics, error reporting, fonts, CDNs or external scripts; no geolocation. The only automatic traffic is the browser loading the site (and the service worker fetching the same site's files).

Everything below happens only when the person taps something:

| Action | What goes where |
|---|---|
| Call / text links (988, 911, 211, Warm Line, trusted people) | Opens the phone app. Prepared texts (for example "I'm having a really hard time. Can you call me?", the code word, check-in ask, kind messages, including "Thank you for [their own words]") go to the Messages app, and from there to whoever the person sends them to. |
| Share sheet / copy (supporter guide link, check-in link, Export) | Goes to whatever app the person picks. The clipboard may sync to the person's other devices (for example Apple's Universal Clipboard). |
| Maps (Change the scene) | Apple or Google Maps receives only the search word ("library", "park", "coffee shop", "community center"). No location from the app. |
| 988 online chat, findahelpline.com, Ko-fi | Opens that website. No `Referer` header is sent: since F7 both the app and the supporter guide set `no-referrer`. |
| Supporter opens the check-in link `zigzagmind.com/support/?for=Name#checkins` | The query string (`?for=Name`) is part of the request to the web host, so it can appear in **server logs**. The `#checkins` part is not sent. Since F1 this is the **person's own first name**, if they chose to give one (optional); that first name can reach the host's logs. |
| Loading the site at all | The host (Render) receives normal request data: IP address, user agent, time, path. **What Render logs and keeps was not checked.** |

## 4. Export and delete

- **Export my data:** shows a JSON copy of the plan, check-ins (state, intervention, ratings, date) and activity (type, date), the first 30 days mode if on (`first30Days`), and kept songs (`songs`). Nothing leaves unless the person copies it.
- **Delete everything:** empties the plan, history, activity, the first 30 days mode and kept songs in memory and in `localStorage` (verified: storage history and activity are 0 afterwards). **Kept:** settings (`next.v1.prefs`, including "onboarded"), and the current visit's safety level (by design: "safety level is never reset").

- **Calendar files (6.13 and check-ins):** built on the phone and handed to the phone's own calendar. Nothing is sent by the app.

- **Find something (camera):** the phone's own camera or photo picker hands the photo to the page (a file input); the app has no camera access of its own and asks for no permission. The preview exists only in the page and is dropped when the person leaves. No image analysis, no AI, nothing uploaded. Kept only on Keep (see `next.v1.noticed`).

- **Feedback form (6.19 F, only when `FEEDBACK_URL` is set):** opens a separate service in a new tab. It receives only what the person types there (plus normal request data). Nothing from the app is sent with it. Shown only as a link on About.

- **Print my plan (6.19 B):** the print view is built in the page only when the person taps Print and is cleared afterwards; the phone's or computer's own print dialog sends it to the printer the person picks. The code word is left out unless they tick "Include my code word" (never saved). Nothing is uploaded.

- **Copy buttons (desktop, no phone):** the prepared message or code word goes to the clipboard only when the person taps Copy. The clipboard may sync to their other devices. Nothing is sent by the app.
