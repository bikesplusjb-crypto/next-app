## 1. What is stored, and where

| Store | Used? | Key / name | Contents |
|---|---|---|---|
| `localStorage` | Yes | `next.v1.prefs` | Settings: reduce motion, haptics, home-screen tip dismissed, onboarded (true/false), country, theme, saving on/off. **The 18+ answer itself is not stored**, only that onboarding was finished. |
| `localStorage` | Yes | `next.v1.sensitive` | **My Plan** (warning signs, things that help, places, trusted people: names, relationships, phone numbers; professional; time and distance plan; things to avoid; reminders; code word with the person's phone digits; who was asked for check-ins, with phone digits) · **check-in outcomes** (state, intervention id, before/after ratings, game/Zags/scene answers, timestamp; last 500) · **activity** (type `moment` / `plan` / `reach`, timestamp; last 500) |
| `sessionStorage` | No | | |
| IndexedDB | No | | |
| Cookies | No | | |
| Service worker cache | Yes | `zz-shell-v3` | App files only: `index.html`, `support/`, manifest, icons. Never user data (the service worker code has no storage access; `pwa.test.js` checks this). |
| In memory only (gone on reload) | | `session`, `ui` | Safety level (GREEN/YELLOW/RED), "I still feel bad" and 9–10 counts, Human First counters, free text being typed, games, Zags state |

- **Saving off** (Settings): nothing is written to `localStorage`, and the saved store is removed.
- **Not encrypted.** Anyone with access to the unlocked phone and browser, or its backups, can read `localStorage`. (Already an open item in HANDOFF.md.)
- **Free text is never stored.** The three-things fields, Thought Parking, the spiral "own step" and "Thank you for ___" are checked and then discarded. Verified after a RED entry: not in `localStorage`, not in `session`/`ui`, not in the page.

## 2. Network: what leaves the phone

**The app makes no network requests of its own.** No `fetch`, `XMLHttpRequest`, `sendBeacon`, WebSocket or EventSource; no analytics, error reporting, fonts, CDNs or external scripts; no geolocation. The only automatic traffic is the browser loading the site (and the service worker fetching the same site's files).

Everything below happens only when the person taps something:

| Action | What goes where |
|---|---|
| Call / text links (988, 911, 211, Warm Line, trusted people) | Opens the phone app. Prepared texts (for example "I'm having a really hard time. Can you call me?", the code word, check-in ask, kind messages, including "Thank you for [their own words]") go to the Messages app, and from there to whoever the person sends them to. |
| Share sheet / copy (supporter guide link, check-in link, Export) | Goes to whatever app the person picks. The clipboard may sync to the person's other devices (for example Apple's Universal Clipboard). |
| Maps (Change the scene) | Apple or Google Maps receives only the search word ("library", "park", "coffee shop", "community center"). No location from the app. |
| 988 online chat, findahelpline.com, Ko-fi | Opens that website. **The browser also sends a `Referer` header** with the app's address (`https://zigzagmind.com/`), because `index.html` sets no referrer policy (see F7). The supporter guide does set `no-referrer`. |
| Supporter opens the check-in link `zigzagmind.com/support/?for=Name#checkins` | The query string (`?for=Name`) is part of the request to the web host, so it can appear in **server logs**. The `#checkins` part is not sent. (Today the name is the supporter's own, because of F1; if F1 is fixed by using the person's name, that name would reach the logs.) |
| Loading the site at all | The host (Render) receives normal request data: IP address, user agent, time, path. **What Render logs and keeps was not checked.** |

## 4. Export and delete

- **Export my data:** shows a JSON copy of the plan, check-ins (state, intervention, ratings, date) and activity (type, date). Nothing leaves unless the person copies it.
- **Delete everything:** empties the plan, history and activity in memory and in `localStorage` (verified: storage history and activity are 0 afterwards). **Kept:** settings (`next.v1.prefs`, including "onboarded"), and the current visit's safety level (by design: "safety level is never reset").
